# 《给我滚》构筑、奖励与九关成长重设计

日期：2026-11-28
状态：方向已由用户确认；本文是待确认的完整设计，不代表已实施或已验证平衡。
范围：保留 Godot 4.6 / Jolt、双键侧推、真实刚体、现有赛道积木与美术，重做局内构筑与成长规则。

## 1. 已确认方向与设计判断

用户反馈：奖励复杂、加成难比较、难以判断是否适合构筑；流派和数值曲线不平滑，乱选也容易过关。用户已确认采用行为驱动构筑、有限等级、可解释收益及九关原型的方向。

本文新增的具体规则、数字、球体模板和奖励节奏均为设计建议，不冒称用户逐项指定。所有初始数值是实验起点；行为契约和验收方法优先于某个系数。

目标：
- 玩家看卡后约 5 秒内能说出触发条件、变化量和是否契合当前跑法。
- 前三关形成明确循环：寻找机会 → 执行动作 → 获得可见收益。
- 同等操作、选卡次数、底盘和种子下，有方向的构筑在后半程稳定优于随机选卡。
- 三个核心各自改变路线选择；通用卡补短板，不能取代核心。
- 失败可追溯到用时、失误、路线和触发机会；不声称能精确分解每张卡节省了多少跑图时间。

非目标：新增输入键、商店、货币、局外养成、背包管理、装备替换、无限关卡、全新地图美术或新增引擎；首版不追求几十种组合。
反目标：自动推荐唯一正确答案；用职业专属障碍强迫某核心；隐藏无效卡；用无条件增速掩盖玩法；把安全钳制当作常规成长曲线。

## 2. 方案比较（Approaches）

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 保留原子物理卡，仅补收益显示与调参 | 改动小，保留已有组合 | 多层乘算和触发条件仍难解释，长期维护困难 | 未采用 |
| 行为驱动核心 + 有限等级 + 可混搭支援 | 跑法清楚，能预测单次效果，保留物理与组合 | 要同步改事件、奖励、关卡和测量 | 用户确认的方向 |
| 固定职业与专属升级树 | 容易入门，平衡空间小 | 自由组合少，容易变成固定答案 | 未采用 |

## 3. 现状证据与必须先修的基础问题

源码与 2026-11-27 的临时 Godot 探针确认：
- `PhysicsSynergyBus.rebuild_stats()` 调用 `StatSheet.reset_modifiers()`，连初始球 base overrides 一起清除。3.2kg 球拿到只改外力倍率的卡后变回 1.5kg。必须让基础底盘与升级修饰的生命周期分离。
- 默认弹性加高弹卡为 0.25 → 0.80 → 1.00 → 1.00，当前抽卡未排除零收益重复卡。
- 同落地速度下，震地自推的质量因子最终约掉；同速度下，殉爆自推会随质量增加而减弱。不能继续用“更重必然让所有输出更强”的文案。
- 当前场景加速带 / 星环 / 桶自推分别约 +18 / +15 / +16 m/s，基础路线收益会掩盖构筑。
- 现有整合测试给第 4 关塞入 7 张卡，只比较约 2 秒的位移和峰速，不能证明合理选卡优于同次数随机构筑。
- 3 个种子 × 第 1/4/8 关的零输入白板探针中，同关有自动通过也有超时。这是小样本线索，不是人类胜率结论。

相关源码：`src/core/stat_sheet.gd`、`src/core/physics_synergy_bus.gd`、`src/upgrades/upgrade_catalog.gd`、`src/gameplay/player_ball_3d.gd`、`src/track/track_generator_3d.gd`、`tests/test_game_loop.gd`。

## 4. 一局流程与状态

流程：选球 → 第 1 关教学 → 三选一选择核心 → 第 2 关 → 强化三选一 → … → 第 9 关 → 胜利结算。

- 第 1 关结束的三张卡固定为三个不同核心，均为 I 级；排列固定，方便学习。没有稀有度抽取，不会抽不到启动卡。
- 第 2～8 关结束共 7 次随机三选一，每次获得一张新支援/改造或已有卡升一级。开第 9 关时合计 8 次选择（核心选择计一次）。
- 每局一个核心，不能再获取另一个完整核心；所有支援对三个核心开放，因此允许跨动作混搭。没有装备槽上限和拆卸操作。
- 第 9 关过线进入 `VICTORY`，不再发卡、不生成第 10 关。超时进入 `GAME_OVER`。两种终态均提供同种子重开/新种子重开。
- 暂停选卡、起始画面和结算时，倒计时、刚体、风场、事件计时器、临时效果均停止；下一关清空临时状态。
- 每关基础 30 秒；剩余时间不结转；全来源累计加时每关最多 4 秒，界面展示已获/上限；剩余时间最大 34 秒。
- 坠落保留现有拉回机制，1.2 秒拉回期间继续计时，落下去的时间和重跑时间仍真实计入；不叠加隐藏罚秒。
- 超时与终点同一物理帧：使用本帧经过时间扣减后判定，剩余时间 > 0 且满足有效过线才胜；剩余时间 <= 0 判超时。终点必须采用实际通行区域判定，不能只靠无限横向范围的 z 坐标。

## 5. 初始球：底盘影响手感，核心决定跑法

保留三种真实形状和现有 3D 预览，外观/涂装由种子变化。首版固定每种形状的物理模板，去掉同形状的大幅随机质量、阻尼和弹性，降低平衡噪声。

| 底盘 | 质量 kg | 等效半径 m | 弹性 | 摩擦 | 线性阻尼 | 主要手感 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 圆球 | 1.5 | 0.55 | 0.30 | 0.42 | 0.32 | 易控制的基准 |
| 橄榄球 | 1.4 | 0.55 | 0.40 | 0.42 | 0.32 | 非对称接触与弹跳 |
| 圆边滚筒 | 1.7 | 0.55 | 0.25 | 0.42 | 0.32 | 更宽的扫障接触面 |

不是职业绑定，三个底盘均可选三个核心。形状导致的有效碰撞尺寸须沿用实际几何，预览准确展示。以上手感需实机验证；不得为让某流派成立而偷偷按底盘修改卡牌收益。

基础模板在整局中持久保存；只在新局/更换初始球时替换。支援卡重算只清修饰器。首版不提供质量、半径或弹性无限成长卡。

## 6. 统一事件与收益计算

### 6.1 真实物理与游戏奖励分工

物理引擎负责碰撞、摩擦、反弹、风力、物体倒下和飞行。卡牌奖励使用明确的前向速度增量 Δv、保速比例、外力加算比例、时间秒数。

离散前向奖励实现为 J = m × Δv，因此质量不同不会暗改标称提速。对真实碰撞保速：以同一物理帧原始碰撞前后前向速度差为损失，各卡恢复比例先加算再统一恢复，最多恢复 60%，不能恢复到碰撞前速度以上。不得把先施加的卡牌奖励算入待恢复损失。

每张卡的等级表直接定义最终效果，重复选取不是重复乘算。预览和运行读取同一份数据/纯计算函数。

取消当前过载全局倍率、共振双次结算和按实时动能递归自推机制。保留爆炸桶真实物理连锁及已有视觉，但连锁不能反向刷出核心触发或额外加时。

### 6.2 有效动作契约

事件携带来源实体 ID、根事件 ID、物理帧号、接触前速度、法线、接触类别、是否玩家直接动作、是否恢复后抑制期；落地还携带腾空时长与向下速度。

- 有效冲撞：玩家直接撞击可移动轻/中木箱、球瓶、可撞开的史莱姆，接触前相对法线接近速度 >= 3 m/s，且实体首次由此接触解锁/倒下。一个实体整关最多计一次。铁砝码/锁定铁块不计，爆炸桶爆炸不计，冲击波/风/其他杂物先撞倒的物体不计。同帧多目标可计破障统计，但核心推进全局冷却 0.35 秒。
- 有效落地：有真实承重接触，腾空 >= 0.40 秒，落地前沿跑道上方向的向下速度 >= 3 m/s；每个腾空周期最多一次；落地核心冷却 0.60 秒。接触缓冲不得把数帧抖动认作新腾空。
- 有效反弹：撞到护栏或固定缓冲桩，法线近似水平（abs(dot(normal, track_up)) <= 0.35），碰前相对法线接近速度 >= 2.5 m/s，碰后法线速度朝离开表面方向 > 0；全局冷却 0.40 秒；同实体须连续离开接触 >= 0.15 秒才重置资格。地板、可移动箱子、连续贴墙不计。
- 复位后 0.50 秒不产生构筑奖励，清除原接触资格与腾空状态，防拉回自带落地收益。
- 碰撞采样只采集事实，由一个入口归一化和去重；`body_entered`、`_integrate_forces`、实体回调不得各自发一次奖励。
- 风和爆炸引起的腾空可以在后续真实有效落地触发弹跳核心；不由爆炸直接合成落地/反弹事件。

### 6.3 数值上限

- 同物理帧全部离散前向奖励（核心、支援、加速带、星环、缓冲桩、桶）累计最大 +12 m/s。先统一收集、按稳定顺序结算，不让多入口绕过。
- 软上限仅作用于上述额外前向提速：前向速度 <= 32 m/s 全额，32～44 m/s 线性递减到 0；>44 不再额外提速。自然下坡、真实反弹、风力不受此软上限影响；保留原总速度 85 m/s 的异常保护。
- 先按本帧原始速度统一结算保速，再以结果计算奖励软上限系数，合并额外 Δv 后施加。所有来源按比例分配被钳制后的实际贡献，保证统计总和等于实际施加量。
- 加时达到 4 秒累计上限后，不再增加时间；达到上限的事件可正常触发其他收益。不得在倒计时减少后重新腾出“累计加时额度”。
- 文案注明高速时提速递减；历史展示实际施加量。质量改变风力加速度的真实影响仍保留。

## 7. 首版卡池：12 个定义

无稀有度强度分层；展示“核心 / 改造 / 支援”、动作标签、等级。三个核心定义只能开局选一个，后续同 ID 升级；3 个改造各有核心前置；6 个支援通用。

### 7.1 三个核心（I / II / III）

| ID / 名称 | 触发 | 各等级完整效果 |
| --- | --- | --- |
| `impact_core` 破阵推进 | 有效冲撞 | 前向 +3 / +4.5 / +6 m/s |
| `landing_core` 落地推进 | 有效落地 | 前向 +4 / +6 / +8 m/s |
| `rebound_core` 反弹推进 | 有效反弹 | 前向 +3 / +4.5 / +6 m/s |

每个核心仅一个主要效果。每张卡的细则可展开查阅，默认说明用动作语言表述。

### 7.2 三个改造（各 1 级，第 4 关结束起解锁）

| ID / 名称 | 前置 | 效果与取舍 |
| --- | --- | --- |
| `impact_chain` 连撞回收 | 破阵推进 | 2.5 秒内第二次有效核心冲撞额外 +3 m/s，并结束这对计数；超时重置。需要找两枚不同目标，不给单次撞击的无条件增益 |
| `landing_wave` 落地清场 | 落地推进 | 有效核心落地发半径 3.5m、最大作用冲量 8 N·s、线性距离衰减的真实物理冲击波；自身核心 Δv 减少 1 m/s。清障产生的位移/爆炸不会触发冲撞核心或回收支援 |
| `rebound_link` 左右接力 | 反弹推进 | 2.5 秒内在左右相反法线方向完成第二次有效核心反弹，额外 +3 m/s，结束这对计数；同侧第二次以该次作为新起点。鼓励有节奏交替 |

核心升级和改造相互兼容，预览必须展示减益；同事件满足额外收益时合并后进入帧上限。

### 7.3 六个通用支援（各最多 II 级）

| ID / 名称 | I → II 级完整效果 | 用途 |
| --- | --- | --- |
| `impact_guard` 缓冲外壳 | 对可移动障碍真实碰撞损失恢复 20% → 35% | 冲撞续航，也帮助其他流派过障碍；铁块不免损 |
| `impact_clock` 破障回收 | 每 4 次有效直接冲撞 +0.4 → +0.7 秒 | 跨流派找障碍；无核心也能触发；不额外提速 |
| `air_ring` 穿环回收 | 每个首次穿过的空中星环额外 +0.3 → +0.5 秒 | 为任何流派提供空中支线，受全关加时上限约束 |
| `external_sail` 借力帆 | 场景有利外力 +15% → +30% | 加速带、星环、缓冲桩、桶、风的前向/上升有利分量；不放大核心与其他支援 |
| `air_steering` 空中舵 | 空中侧推系数 0.65 → 0.80 → 0.95（未持有/I/II） | 控制落点，无固定前向推进；地面侧推不变 |
| `slime_guard` 防粘涂层 | 粘液额外阻尼减少 40% → 70% | 绕路与穿越的选择，未持有时仍可操作绕开；不降低普通阻尼 |

说明：最后两张为控制/路线支援，不虚构“预计省时”。如果标准关卡中没有足够适用机会，应先调整关卡预算或替换该卡，再扩卡池。支援不带负面随机词缀。

## 8. 抽卡与成长节奏

资格：非满级、核心前置满足、到解锁关卡、按当前状态能产生非零效果。对已饱和属性不投放；适用机会来自固定关卡计划，不依据玩家上一关碰巧有没有触发决定淘汰。

- 第 1 关固定三核心。
- 第 2～8 关的槽位 A：从当前核心的下一等级和已解锁的本核心改造中均匀选一个，若全满则补通用候选。
- 槽位 B：六种支援中符合资格的候选均匀选一个。
- 槽位 C：优先选与 B 不同用途组的支援，组为破障（guard/clock）、空中（ring/steering）、环境（sail/slime）。不足则从所有其余合格选项补齐。
- 同批三个 ID 不重复。槽位确定后用独立抽卡 RNG 打乱显示顺序，防固定按 1 等价于永远深化核心。
- 每次只升级一级，不跨级。核心/支援下一等级使用同一 ID 与 level 表，购买/选取记录保存顺序与前后等级。
- 理论容量：核心额外两级 + 一张改造 + 六种支援各两级，远多于七次强化，所以正常流程不应枯竭。防御行为为显示实际合格数量并允许确认；不能静默发无效卡。测试保证首版所有合法可达状态均有三项。
- 不增加重抽按钮和货币。随机抽卡结果受同种子、同历史选择、规则版本共同决定；更换选择可改变之后卡池，但不得改变赛道。

本方案不是让流派必须抽到三件套才能启动：I 级核心即可工作。满级核心也不会自动获得改造。

## 9. 关卡预算与九关难度

### 9.1 确定性结构

原来“随机拼到超过目标长度”改为每级固定积木多重集合，再在合法连接约束内随机排列、镜像、移动槽位。开头固定一块 StraightWide，起步平台 10m。下面为初始结构，长度来自现有积木；不含终点后缓冲平台。

记 S=StraightWide(26)、W=WaveHills(30)、N=NarrowBridge(24)、P=SplitPath(32)、R=RampGap(28)、B=PinballAlley(26)、F=FunnelGauntlet(30)。

| 关卡 | 固定积木集合 | 总长 m | 主要任务 |
| --- | --- | ---: | --- |
| 1 | 2S + W + B | 118 | 无核心也宽松可过，展示三类动作 |
| 2 | 2S + W + B + P | 150 | 核心首次完整使用 |
| 3 | 2S + W + 2B + P | 176 | 三种触发机会与一次路径选择 |
| 4 | 2S + W + 2B + P + N | 200 | 初次无护栏控制，奖励后解锁改造 |
| 5 | 2S + 2W + 2B + P + N | 230 | 落点与连续障碍 |
| 6 | 2S + 2W + 2B + 2P + N | 262 | 多次路线取舍 |
| 7 | 2S + 2W + 2B + 2P + N + R | 290 | 跳台与长组合 |
| 8 | 2S + 2W + 2B + 2P + N + R + F | 320 | 多种挑战连续处理 |
| 9 | 2S + 2W + 3B + 2P + N + R + F | 346 | 完整终局检验 |

表中数字是结构基线，不保证已经达到难度目标。调整长度时改固定集合并重测，不能回到无预算的长度随机。

同级同一集合在所有种子下总长一致。HUD、奖励页和结算显示生成后实际长度；关卡预测从同一 LevelPlan 读取。海拔变化按现有跑道局部轴向长度定义，不宣称为球的真实轨迹长度。

### 9.2 机会、危险和基础资源预算

- 现有各块自动放大量加速带/环/桶/高空层/风的逻辑改为候选槽位，LevelPlan 决定启用数量；已禁用的槽位不生成隐藏物理对象。
- 第 1 关无风、粘液、铁块、坠崖必经段。通过 S/W/B 展示轻障碍、低跳台、缓冲桩，中央线安全；零输入能通过教学关可以接受。
- 第 2 关起，每关有至少 6 / 8 / 10 个可直接冲撞目标（关 2～3 / 4～6 / 7～9），至少 2 / 3 / 4 处可完成有效落地的路线，以及至少 3 / 4 / 5 处反弹机会。是可访问机会，并非强制命中数量；可在同一路段共存。
- 所有底盘白板均能走完整几何路线；不能要求拥有空中舵才能跳过必经缺口。每段硬障碍留绕行空间。
- 轻/中/重障碍分档，质量使用现有真实值，不按关数无限加质量。困难来自组合和空间，不来自不可读的物体数值成长。
- 前三关不叠侧风与无护栏段。关 4～6 至多一段复合危险，关 7～9 至多两段；必须留可控制的安全通路。相邻两块不能连续安排强迫起跳后立刻侧风窄桥；用有限可行排列预先筛选，不做无限重抽。
- 同级风场数量、风向类别、强度档位和长度预算固定；只允许镜像与合格槽位变化。连续物理推力的收益必须纳入整段实测，不能只数离散设施。
- 高空层首版从第 4 关起每关最多一条可选支线，固定有可达入口/可控落点。它所含的环/桶计入全关预算，不是额外随机赠送。

基础资源起始预算（同级所有种子完全相同的数量）：

| 关卡 | 加速带 | 星环 | 桶 | 固定缓冲桩 | 风场 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 1 | 0 | 2 | 0 |
| 2～3 | 1 | 2 | 1 | 3 | 1 |
| 4～6 | 2 | 3 | 2 | 4 | 1 |
| 7～9 | 2 | 4 | 2 | 5 | 2 |

星环必须有可达的起跳方式；跳跃流的有效落地点可以不含星环。反弹机会包含已有护栏，固定缓冲桩不需要对应每块 PinballAlley 同样数量。至少每关一个非必经可绕开的粘液区域（第 2 关起），让防粘有稳定用途。

基础离散前向收益改为：加速带 +4 m/s、星环 +2 m/s 并 +0.2 秒、缓冲桩前向 +2 m/s（保留真实法线弹开）、桶近处最多 +3 m/s（保持距离衰减）。同一加速带、缓冲桩的附加前向奖励、桶和星环对玩家每关最多一次；缓冲桩真实弹开可重复，核心反弹按自己的资格重复。

风场的物理表现保留，不统一削弱成看不见的风；先限制数量/覆盖长度与位置，再用路线仿真调强度。质量差异真实影响风响应。

### 9.3 难度目标

统一尺度：过关余量 = 30 + 实际累计加时 − 完成实际路线耗时。失败记录完成率与剩余距离，不把未通关样本当作 0 秒用时或排除。

原型调参目标（待测，不当作已验证事实）：
- 合理构筑配熟练操作，关 1～3 中位余量约 6～12 秒；关 4～6 约 3～7 秒；关 7～9 约 1～4 秒。
- 三个核心在各自适合的操作策略下，后半程的中位通过余量差控制在约 2 秒内；某一核心不能在所有路线与操作策略上支配其他核心。
- 同等操作、同机会预算下，有方向选卡相对随机选卡应改善后半程过关率和余量；原型暂用关 7～9 成功率至少相差 15 个百分点或配对余量中位优势至少 2 秒作为诊断目标，同时检查没有通过全样本失败制造虚假优势。
- 对同核心/底盘/操作策略，种子间的关 4～9 用时 P90-P10 目标 <=4 秒（同时报告失败率）；异常种子要逐个回放。
- 无输入只用于检测基础馈赠/卡死和几何问题，不作为“玩家选卡重要性”的主测试。

如所有构筑都太容易，优先减少被动推进和调整挑战组合；如所有构筑都失败，优先检查路线可达性、动作触发和基础速度，再改计时。不得一开始就同时提高长度、削减时间、堆障碍。

## 10. 玩家信息与反馈

保留现有暖色卡片和 3D 球预览。本轮重点是内容，不另做视觉风格改版。

奖励页文本结构：

```text
第 4 / 9 关完成                 下一关：230m · 连续障碍 / 起伏
本关：耗时 24.3s · 获得加时 0.8s · 坠落 1 次
当前：落地推进 II / 空中舵 I / 穿环回收 I

落地推进 II → III                [核心 · 落地]
有效落地后前向提速：+6 → +8 m/s
单次增加：+2 m/s
上一关有效触发：4 次
高速时提速递减；展开查看触发条件
```

- 新卡显示“未持有 → I”，升级显示当前完整效果 → 新完整效果；同时改变收益和代价必须都显示。
- 通用文案不用“原子、乘区、√Ek”作为主要信息；物理参数只放详情。
- 不显示总战力、伪精确过关率或“预计节省 X 秒”。历史次数仅说明上一关，不承诺下一关同次数。
- HUD 常驻：第 n/9 关、时间、实际剩余轴向距离、速度、核心及等级、核心触发/改造进度。动作收益短提示如“落地推进 +6m/s”“破障回收 +0.4s”；钳制时显示实际值。
- 徽标/提示既用文字也用图形，不能只靠颜色区分核心。暂停后提示动画冻结。
- 结算显示胜/负、完成关数、种子、底盘、构筑、每关耗时/加时/坠落/有效核心触发。保留峰速为次要趣味统计，移除主导性的动能和全局乘区展示。
- 1280×720 支持键盘 1/2/3、A/D、确认键与鼠标，卡片正文不截断；更多细则可展开，不能依赖只能鼠标 hover 的提示。

## 11. 数据与实现边界

建议职责（具体文件命名由实施者决定）：
- `RunState`：9 关状态、累计加时上限、选卡历史、胜负、统计引用；临时计数不跨关。
- `StatSheet`：持久底盘 + 可重建修饰器；支持无副作用预览。
- `UpgradeDefinition/Catalog`：等级效果表、核心/支援/改造分类、动作标签、前置、解锁、最大等级、资格与说明；移除旧稀有度权重语义。
- `PhysicsSynergyBus`：消费归一事件并产出带来源的收益意图，不直接生成下一层可奖励事件。
- `PlayerBall3D`：真实物理采样、接触资格、一次性施加奖励、复位抑制；不硬编码每张卡文案。
- `LevelPlan/TrackGenerator3D`：固定集合、资源槽位预算、机会校验、独立赛道 RNG；赛道不读取持有卡决定生成物。
- `RunTelemetry`：每关记录事件、实际增速、实际保速、被钳制量、加时、路径选择/进度、坠落、触发机会与完成情况；支援没有拿到时也记录基础动作次数，供奖励页历史参考。
- UI 消费同一状态与效果计算结果；选择预览不改真实等级、不推进 RNG、不清空临时计数。

规则版本写入日志和种子分享信息；同种子仅保证同版本、同引擎条件下确定性生成，不承诺跨版本复现旧路线或 Jolt 跨平台位级轨迹一致。

旧卡定义退出活动卡池；旧基于连锁倍率的断言改成新行为契约，不为了旧断言保留隐形旧效果。当前项目没有局内存档承诺，因此不做旧构筑存档迁移；同种子旧卡序列不兼容须在开发说明中注明。

## 12. 验证与调参方法

### 12.1 必须自动验证的契约

1. 每种底盘拿到任意卡并重复重算后，未被该卡修改的基础属性保持原值；新局清理正确。
2. 每张卡各等级、前置、满级退池；合法可达奖励状态有三项不同且有效选项；同种子同历史可复现；不同选择不改地图。
3. 同接触多回调不重复奖励；同目标多次/连锁/风吹不刷冲撞；贴墙不刷反弹；地面抖动和复位不刷落地。
4. 同帧多奖励只计算一次保速和上限；实际贡献合计等于最终施加量；速度钳制和加时累计上限覆盖边界。
5. 关卡开始清空连撞配对、反弹配对、实体奖励资格、事件冷却和每关额度；暂停无任何推进。
6. 九关过线胜利，超时失败，无第十关/第九关选卡；有效终点范围与同帧超时规则成立。
7. 固定集合总长和 UI 一致；至少 100 种子检查全级资源计数、布局净距、连接约束、每类机会预算和高空支线可达入口。
8. 奖励页预览和运行效果一致，满级不出现，无副作用；核心/改造/支援共同触发时仍正确。

### 12.2 仿真与人工试玩分开

- 单独输出固定种子基准报告，不把随机通过率硬塞进易波动的单元测试。
- 开发集 20 个固定种子；验收集另留 30 个未用于调参的种子。失败样本保留日志，不挑选最好种子展示。
- 基准至少比较：无强化白板、随机合格选卡、有方向选卡。后两者每局享有相同核心选择机会与七次强化机会；随机策略也持有同一核心，随机仅作用于七次强化，避免把核心差异当作选卡收益。
- 先使用固定底盘控制变量，再对其余底盘验证；三核心分别与冲撞/落地/反弹策略组合，观察专长与错配。
- 操作代理只能用当前可见/近距离几何和自身状态作路线决策，不使用未生成未来奖励或直接改速度/位置。代理允许实现简化的避障/寻跳台/寻反弹策略；策略算法细节留实施者决定，必须记录版本。
- 独立关卡实验：将同等合法选择数量的构筑在同关同种子跑完整关，避免早期失败导致后期只剩强者样本。整局实验：从第 1 关真实选卡到终局，报告到达率、胜率与总用时，不能给第 4 关塞七张卡。
- 报告成功率、失败进度、完成者时间分布、有效触发次数、各来源贡献、坠落、加时封顶率、高速收益削减占比。单次 Δv 累计不是最终速度或省时，不混用单位。
- 再进行人工试玩，至少包含首次接触和熟悉操控两组（每组先 3 人用于找问题，不能宣称统计显著）；测试能否说清选卡理由、三个流派是否改变路线、失败是否可理解。
- 无法获得真实玩家测试时明确标记未完成，不能用自动代理替代并宣布所有体验目标达成。

### 12.3 交付验证

保持现有几何/物理/起始预览回归；按新设计调整受影响断言。桌面实际渲染检查起始、三核心选择、普通强化、玩法提示、胜利、失败六类状态；运行项目完整测试与 Web 构建，进行 Web 主要流程冒烟测试。

## 13. 实施切分与完成定义

这是跨数值、规则、UI、关卡的一个项目，分三个可审阅阶段，但最终目标包含全部：
1. 可信基础：底盘生命周期、归一事件、统计、九关状态与效果计算数据。
2. 可玩原型：12 个卡定义、分槽抽卡、收益对比、固定关卡预算、旧效果退场。
3. 校准与验收：固定种子基准、逐核心/底盘比较、人工试玩反馈、视觉/Web 回归。

每阶段保持可以启动游玩；不同时保留两个玩家可见的奖励系统。具体类拆分、测试组织、纯计算函数形式、布局细节由实施者决定；不得自行改变核心数量、单局选择次数、加时规则或恢复全局指数乘区。

完成不能只写“测试全绿”：必须交付数值版本、完整奖励表、基准报告、仍未完成的人工验证项。若原型目标不成立，先定位机会不足/触发不稳定/被动收益过大/操作代理偏差，再调整系数，记录理由。
